# Native Isolation & PE Patching Extension Plan (2026-11-14)

## Review update (2026-11-15)

Only this dated plan is being implemented; `astra_plan.md` is reference context.
The current source already rejects embedded NULs and validates raw call
signatures through `RawCallSignature.Validate`. UNM-01 is a verification gate,
not a request to duplicate those fixes. Preserve the pre-existing CI edit.

Additional requirements from downstream native host reviews:

- **UNM-02:** preflight the complete requested patch set before publishing any
  worker file. Check bounded PE headers, architecture, unmanaged DLL status,
  section-backed RVA ranges, import/delay-import tables and string terminators.
  Reject ambiguous duplicate matches, truncated/overflowing images, non-ASCII
  names, paths in module names and unsupported layouts. Same-or-shorter names
  require explicit idempotence metadata because a shortened import can no
  longer be found by its original name. Never scan-and-replace arbitrary bytes.
  Signature/checksum changes affect only private copies, not source binaries.
- **UNM-03:** a stable worker slot alone is not a process-wide unique module
  identity. Separate pools and overlapping recycle generations need distinct,
  bounded namespaces. Validate fixed-length names for collisions, support
  explicit per-module names/verified dynamic-load literal patches, and handle
  transitive import graphs deterministically. Do not imply that renaming
  ordinary import descriptors also rewrites delay imports or `LoadLibrary`
  string literals. Load/unload on the owning thread where a runtime requires
  first-thread TLS lifetime. Never change process current directory or the
  process DLL search path.
- **UNM-04:** an execution scope preserves the caller's floating-point control
  modes and thread error mode, clears pending exceptions before restoring
  masks, and is thread-affine/idempotent. Do not replace rounding/precision
  settings with an unconditional `_fpreset`. Process-wide dialog suppression
  remains an explicitly named operation, not a hidden scope side effect.
- **UNM-05:** raw addresses remain valid only while the library is alive.
  Validate disposed instances and handles consistently and document the
  concurrent-disposal boundary rather than promising a permanent pointer lease.
- **UNM-06:** a stale-directory sweeper needs an ownership marker, an exclusive
  live-set lease and strict root/path validation. Delete only directories
  created by this library; skip active, unknown and locked directories. Test
  partial staging failure, duplicate disposal and failed deletion.

Numeric VB6 scratch resets, PowerBASIC TLS-template replacement, Delphi
SAFEARRAY/finalization fixes and Fortran sharing-table patches remain explicit,
binary-verified application policies. The reusable editor provides primitives,
not guessed offsets or automatic patch discovery.

## Executive summary

`UnmanagedLibrary` (`v5.0.0`) provides clean, safe single-module `LoadLibraryEx` / `TryGetExport` / `GetUnmanagedFunction<TDelegate>` primitives. However, real-world legacy calculation DLLs share three structural characteristics that required every downstream host to build ~400–600 lines of custom native-isolation and PE-patching infrastructure on top of `UnmanagedLibrary`:

1. **Process-global mutable `.data` / `.bss` state and transitive runtime singletons:**
   - Legacy C/C++, Delphi, PowerBASIC, and Fortran DLLs keep calculation inputs, unit tables, scratch buffers, and error state in writable `.data`/`.bss` sections (often 64 KiB – 2 MiB).
   - Simply calling `LoadLibraryEx("C:\\app\\lib\\engine.dll")` `N` times returns the **same `HMODULE`** (`refcount = N`) sharing one `.data`/`.bss` segment across all worker threads!
   - Even copying `engine.dll` into `worker_00\engine.dll` and `worker_01\engine.dll` is **insufficient when `engine.dll` imports a stateful companion DLL** (for example, Digital Visual Fortran's `DFORRT.dll` whose global Fortran logical-unit I/O table lives inside `DFORRT.dll`'s `.data` section, or multi-DLL calculation graphs `A.dll -> B.dll -> C.dll`) because Windows loader unifies companion modules by their internal PE import-descriptor DLL name (`IMAGE_IMPORT_DESCRIPTOR.Name`) once loaded in the process unless the companion DLL filenames AND import-table references are rewritten per worker (`DFOR00.dll`, `DFOR01.dll`)!
2. **Repeated boilerplate for verified, deterministic PE32 / PE32+ binary patching:**
   - Across 15+ native integrations, downstream code had to reimplement `System.Reflection.PortableExecutable` (`PEReader`) validation + RVA-to-file-offset translation + exact-byte/ASCII verification before rewriting:
     - Fixed-length import module names (`DFORRT.dll` -> `DFOR00.dll`) for transitive multi-DLL worker isolation,
     - Unused GUI/INI import-by-name entries absent on Windows Nano Server (`IMAGE_IMPORT_BY_NAME`),
     - PE optional-header checksum recalculation and idempotent write-if-changed file staging.
3. **Post-call floating-point control-word (x87 FPU / MXCSR) and Win32 error-mode hygiene:**
   - Legacy 32-bit Delphi, Borland C++, and Fortran DLLs frequently unmask x87 floating-point exceptions (`_control87` / `FLDCW`, unmasking `#ZE`, `#OE`, `#IE`) inside `DllMain` or calculation entry points, causing **subsequent unrelated managed double math or JIT code** on the same thread to crash the process with `STATUS_FLOAT_DIVIDE_BY_ZERO` (`0xC000008E`) or `STATUS_FLOAT_INVALID_OPERATION` (`0xC0000090`)!
   - Legacy DLLs also call `MessageBoxA` / system error popups on missing files unless process/thread `SetErrorMode` (`SEM_FAILCRITICALERRORS | SEM_NOGPFAULTERRORBOX | SEM_NOOPENFILEERRORBOX = 0x8007`) is active.

### UNM-02 (P0): Verified PE32 / PE32+ image patcher (`PeImagePatcher`)

#### Evidence
Downstream consumers currently maintain duplicated PE manipulation helpers to:
- Verify expected file length, `MZ`/`PE\0\0` signatures, `Machine` (`I386` / `Amd64`), `PEMagic` (`PE32` / `PE32Plus`), `IsDll`, and unmanaged image status (`CorHeader == null`) before touching a single byte;
- Translate RVAs to raw file offsets across section headers (`VirtualAddress`, `VirtualSize`, `SizeOfRawData`, `PointerToRawData`);
- Rewrite `IMAGE_IMPORT_DESCRIPTOR.Name` strings (same-or-shorter ASCII length, NUL-padded) so worker copies bind to worker-private companion DLLs;
- Rewrite `IMAGE_IMPORT_BY_NAME` symbol names (preserving or clearing the 2-byte `Hint`) when redirecting unused legacy imports;
- Apply verified exact-byte patches (`expectedOriginal` OR `alreadyPatched` idempotence check -> `BadImageFormatException` on mismatch);
- Write output files atomically/idempotently (`WriteBytesIfChanged` comparing length + streaming byte equality so warm restarts do not dirty or fail on unchanged files).

#### Design
 keep `AdaskoTheBeAsT.Interop.Unmanaged` dependency-light (using `System.Reflection.PortableExecutable` on `net8.0+` and a compact built-in COFF/PE header parser on `net462`–`net481`, requiring **zero extra NuGet dependencies**):

```csharp
public sealed class PeImageEditor
{
    public static PeImageEditor FromFile(
        string sourcePath,
        PeImageValidationOptions? validation = null);

    public ushort Machine { get; }
    public bool IsPe32Plus { get; }

    public int RvaToFileOffset(uint rva);

    public PeImageEditor RewriteImportModuleName(
        string originalModuleName,
        string replacementModuleName);

    public PeImageEditor RewriteImportSymbol(
        string moduleName,
        string originalSymbolName,
        string replacementSymbolName);

    public PeImageEditor ReplaceVerifiedBytesAtRva(
        uint rva,
        ReadOnlySpan<byte> expectedOriginal,
        ReadOnlySpan<byte> replacement);

    public PeImageEditor ClearAuthenticodeAndRecalculateChecksum();

    public byte[] ToArray();
    public void SaveIfChanged(string destinationPath);
}
```

#### Key invariants
- `replacementModuleName` UTF-8/ASCII byte length MUST NOT exceed `originalModuleName.Length` (enforced with `ArgumentOutOfRangeException`), and any trailing bytes up to the original NUL terminator are zero-filled.
- Every `Rewrite*` and `ReplaceVerifiedBytesAtRva` method verifies that the target bytes match either `expectedOriginal` or `replacement` (idempotent), throwing `BadImageFormatException` with the file name and RVA/offset if an upgraded native binary shifted layout.
- If a PE carries `IMAGE_DIRECTORY_ENTRY_SECURITY` (`Authenticode`) or `IMAGE_DLLCHARACTERISTICS_FORCE_INTEGRITY`, `ClearAuthenticodeAndRecalculateChecksum()` strips the invalidated signature table on the private worker copy and updates `OptionalHeader.CheckSum`.

#### Acceptance
- Tested against real x86 (`PE32`) and x64 (`PE32+`) native C test DLLs compiled in `test/native`: import-module rename, import-symbol rename, RVA byte patch, mismatch rejection (`BadImageFormatException`), and idempotent `SaveIfChanged`.

### UNM-03 (P1): Per-worker isolated native library set (`IsolatedLibrarySet`)

#### Evidence
When hosting stateful native DLLs inside an `ExecutionWorkerPool<TSession>` with `N` workers:
- **Single-DLL case:** Copying `calc.dll` to `<root>\w00\calc.dll`, `<root>\w01\calc.dll`, ... and loading with `LOAD_LIBRARY_SEARCH_DLL_LOAD_DIR | LOAD_LIBRARY_SEARCH_DEFAULT_DIRS` gives each worker a distinct `HMODULE` and independent `.data`/`.bss` pages.
- **Multi-DLL graph case (e.g., `Engine.dll -> DFORRT.dll` or `A.dll -> B.dll -> C.dll`):** Even if `DFORRT.dll` is copied into both `<root>\w00\DFORRT.dll` and `<root>\w01\DFORRT.dll`, Windows' loader module list matches loaded DLLs by **base module name** (`DFORRT.dll`) during implicit import resolution unless each worker's DLLs carry distinct module filenames (`DFOR00.dll`, `DFOR01.dll`) and patched `IMAGE_IMPORT_DESCRIPTOR.Name` entries!

#### Design
Provide a declarative builder for per-worker isolated native module sets:

```csharp
public sealed class IsolatedLibrarySetOptions
{
    public required string SourceDirectory { get; init; }
    public required string IsolationRootDirectory { get; init; }
    public required int WorkerIndex { get; init; }
    public bool DeleteDirectoryOnDispose { get; init; } = true;
}

public sealed class IsolatedLibrarySet : IDisposable
{
    public string WorkerDirectory { get; }
    public IReadOnlyDictionary<string, UnmanagedLibrary> Libraries { get; }

    public UnmanagedLibrary GetLibrary(string logicalName);
    public void VerifyDistinctFrom(IsolatedLibrarySet other);
}
```

With worker-slot naming helper `WorkerModuleNaming.FormatFixedLengthName(string originalFileName, int workerIndex)` that replaces the last 2 stem characters before `.dll` with zero-padded `workerIndex` (`00..99`, e.g., `"DFORRT.dll"` -> `"DFOR00.dll"`, `"runtime9620.dll"` -> `"runtime9600.dll"`), preserving exact ASCII string length for PE import descriptors!

#### Acceptance
- Native integration test builds `parent.dll` (mutable global counter) importing `child.dll` (mutable global counter), instantiates two `IsolatedLibrarySet` instances (`workerIndex: 0` and `workerIndex: 1`) in the same process, mutates both concurrently across 10,000 iterations, and verifies:
  1. `parent` and `child` `HMODULE` addresses differ between worker 0 and worker 1;
  2. Zero cross-worker state leakage occurs in either `parent.dll` or `child.dll`;
  3. `Dispose()` frees handles in reverse topological order and deletes the worker directory cleanly.

### UNM-04 (P1): x87 FPU / MXCSR & Thread Error-Mode Guard (`NativeExecutionGuard`)

#### Evidence
32-bit Delphi (`SysInit._InitLib` sets x87 CW to `0x1332`, unmasking divide-by-zero, overflow, and invalid-operation traps!) and legacy Fortran (`DFORRT.dll`) mutate the thread's x87 FPU control word during `LoadLibrary` (`DllMain`) and calculation calls. On x86 .NET (`win-x86`), CoreCLR and managed floating-point code assume IEEE-754 masked exceptions (`0x027F` / `0x037F`); leaving `#ZE` or `#IE` unmasked causes `double.NaN` or `1.0 / 0.0` in managed code to fault with hardware `0xC000008E` / `0xC0000090`!

#### Design
Add a lightweight `NativeExecutionGuard` utility:
- `NativeExecutionGuard.SuppressProcessErrorDialogs()`: calls `SetErrorMode(SEM_FAILCRITICALERRORS | SEM_NOGPFAULTERRORBOX | SEM_NOOPENFILEERRORBOX)` (`0x8007`) and `SetThreadErrorMode` where supported on Windows (no-op on Linux/macOS).
- `NativeExecutionGuard.ResetFloatingPointState()` (and `using var scope = NativeExecutionGuard.EnterScope()`): on Windows x86, invokes `msvcrt!_controlfp_s` (`_MCW_EM`, `_MCW_EM`) + `_clearfp()` to mask all x87/SSE exceptions after `LoadLibraryEx` (`DllMain`) and after native P/Invoke calls that unmask FPU traps.

#### Acceptance
- Native x86 test DLL deliberately unmasks x87 `#ZE`/`#IE` via `_control87(0, _EM_ZERODIVIDE | _EM_INVALID)`; calling it inside `NativeExecutionGuard` restores masked IEEE-754 state so subsequent managed `0.0 / 0.0` produces `double.NaN` instead of crashing the process.

### UNM-05 (P1): `GetExportAddress` / `GetRequiredExport` ergonomics & module address bounds

#### Evidence
High-throughput native wrappers on `net8.0+` use C# `delegate* unmanaged[Stdcall]<...>` function pointers (zero delegate/marshaling allocation) over `UnmanagedLibrary.TryGetExport(handle, name, out IntPtr address)` (`UnmanagedLibrary.cs:145`), writing repetitive `if (!lib.TryGetExport("FOO", out var pFoo)) throw new EntryPointNotFoundException(...)` blocks for 15–30 exports per DLL. Callers clearing leaked `.bss` slots after native calls also need `IntPtr BaseAddress` on `UnmanagedLibrary`.

#### Design
Add non-breaking convenience members to `UnmanagedLibrary`:
```csharp
public IntPtr BaseAddress { get; }

public IntPtr GetRequiredExport(string functionName);

public static IntPtr GetRequiredExport(SafeLibraryHandle safeLibraryHandle, string functionName);
```
Throwing `EntryPointNotFoundException` with both the export name and module identifier when missing, while keeping `DangerousAddRef` / `DangerousRelease` handle safety around `NativeLoader.GetExport`.

#### Acceptance
- Unit tests across all 9 TFMs verify `BaseAddress`, `GetRequiredExport` success path, `EntryPointNotFoundException` message clarity, and `ObjectDisposedException` after `Dispose()`.
