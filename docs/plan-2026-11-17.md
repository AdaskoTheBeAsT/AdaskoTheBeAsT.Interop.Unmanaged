## Executive summary

`UNM-01` through `UNM-06` delivered verified offline PE import/byte patching (`PeImageEditor`), multi-DLL worker isolation (`IsolatedLibrarySet` + `WorkerModuleNaming`), FPU/error-mode guards (`NativeExecutionGuard`), and `GetRequiredExport` / `BaseAddress`. Cross-checking downstream native host implementations reveals seven remaining unmanaged-only capabilities that still require 250–400 lines of custom Win32/PE boilerplate per consumer:

1. **Incomplete offline PE table coverage for Nano Server & multi-DLL worker renaming:**
   - Multi-DLL C++/Delphi/Fortran suites (`corecalc.dll`, `solverrt.dll`, `meshdata.dll`) store the DLL's own internal module name inside `IMAGE_EXPORT_DIRECTORY.Name` (`DataDirectory[0]`) in addition to `IMAGE_IMPORT_DESCRIPTOR.Name` (`DataDirectory[1]`). Today consumers patch raw hardcoded file offsets to update export-table names.
   - Legacy DLLs and helper `.exe` binaries (`calcworker.exe`, `legacyengine.dll`) often carry whole `IMAGE_IMPORT_DESCRIPTOR` entries for GUI/audio/ODBC modules absent on Windows Nano Server (`oledlg.dll`, `winmm.dll`, `odbc32.dll`, `winspool.drv`). Rewriting individual symbols cannot rescue load time when the imported DLL itself does not exist on disk; the unused 20-byte `IMAGE_IMPORT_DESCRIPTOR` entry must be compacted out of the import directory table.
   - Verified fixed-slot ASCII, UTF-16LE (`Wide`), and length-prefixed string patches plus setting `IMAGE_FILE_LARGE_ADDRESS_AWARE` (`0x0020`) on 32-bit helper/apphost `.exe` images still require manual byte encoding and COFF header bit twiddling.
2. **Runtime loaded-module (`HMODULE`) IAT hooking & verified in-memory resets:**
   - Multiple integrations redirect individual imported Win32 APIs (`SHGetFolderPathW`, `RegCreateKeyExA`, `OleCreate`, `CoCreateInstance`) inside already-loaded native modules via `VirtualProtect` on mapped IAT slots (`OriginalFirstThunk` + `FirstThunk`), patch verified RVA ranges in memory when disk copies are shared, or zero verified `.data`/`.bss` scratch ranges between operations so worker sessions can be reused without unloading/reloading the DLL.
3. **Address-to-module provenance verification:**
   - Multi-worker tests and diagnostics repeatedly wrap `GetModuleHandleExW(GET_MODULE_HANDLE_EX_FLAG_FROM_ADDRESS | GET_MODULE_HANDLE_EX_FLAG_UNCHANGED_REFCOUNT, ...)` + `GetModuleFileNameW` to prove that an export pointer, callback target, or vtable slot belongs to a worker's isolated DLL copy rather than a shared module.
4. **Companion asset staging, legacy path limits, and process-pinned modules in `IsolatedLibrarySet`:**
   - Real worker directories almost always stage non-DLL companion assets (`.ini`, `.mem`, `.dcp`, `.mdb`, `.dat`, `.manifest`), enforce legacy `MAX_PATH` / 120-character ASCII path limits (Jet 4.0, Fortran `CHARACTER*128`, Delphi ANSI I/O), or intentionally pin loaded `HMODULE`s for process lifetime when legacy DLLs spawn background threads that make `FreeLibrary` unsafe.
5. **Bounded `00..99` worker slot leasing for short 8.3 module names:**
   - Short DLL stems (`core.dll` -> `co00.dll`, `io00.dll`) have no room for a generation token; dynamically recycled sessions need a thread-safe bounded slot lease (`0..99` with optional reserved/excluded indices) so retiring and replacement sessions never collide.
6. **Zero-allocation fixed-buffer C / Fortran / Delphi string marshaling & `win-x86` `LARGEADDRESSAWARE` build support:**
   - Almost every native wrapper duplicates `Span<byte>` helpers for NUL-terminated ASCII/Latin1 buffers, space-padded Fortran `CHARACTER*N` buffers, and length-prefixed Delphi `ShortString`s, alongside an MSBuild post-build target setting `LARGEADDRESSAWARE` on 32-bit `win-x86` apphosts so pools with 10+ isolated native DLL sets can address 4 GiB instead of 2 GiB on 64-bit Windows.
7. **Fault-evicting process-pinned export handle caching & reusable native scratch buffers (`SafeBuffer`):**
   - Multiple unload-unsafe Borland Delphi, PowerBASIC, and MFC wrappers duplicate static handle-cache dictionaries (`ConcurrentDictionary<string, NativeHandles>` or `Lazy<NativeHandles>` + static `NativeLoadLock` + `#pragma warning disable CA2000, IDISP001, IDISP003`) to reuse process-pinned `UnmanagedLibrary` / `IsolatedLibrarySet` handles, bound export delegates, and one-time native path initializers across session recyclings without permanently caching transient load failures, alongside custom `Marshal.AllocHGlobal` / `SafeBuffer` scratch buffers for `ref char*` / raw pointer ABIs.

## Detailed technical plan

### UNM-07 (P0): Extend `PeImageEditor` with export-name rewrites, import-descriptor compaction, verified string patches & COFF characteristics

#### Evidence
- **Export directory module name (`DataDirectory[0]`):** Multi-DLL C++/Delphi/Fortran libraries inspect or advertise their internal `IMAGE_EXPORT_DIRECTORY.Name` string. Currently `PeImageEditor` rewrites `IMAGE_IMPORT_DESCRIPTOR.Name` and `ImgDelayDescr.szName`, forcing callers to hardcode raw file offsets for export-header names.
- **Whole `IMAGE_IMPORT_DESCRIPTOR` removal (`DataDirectory[1]`):** Binaries importing `oledlg.dll`, `winmm.dll`, or `odbc32.dll` fail `LoadLibraryExW` / process startup on Windows Nano Server before any code runs. Shifting subsequent 20-byte `IMAGE_IMPORT_DESCRIPTOR` records left by one slot and zero-filling the vacated trailing descriptor removes the load-time dependency deterministically while keeping `DataDirectory[1].VirtualAddress` valid.
- **Verified ASCII / UTF-16LE / length-prefixed string patches & `LARGEADDRESSAWARE`:** Callers repeatedly construct `PeVerifiedBytePatch` byte arrays manually for NUL-terminated ASCII strings, NUL-terminated UTF-16LE literals (`Wide: true`), and Delphi Pascal `ShortString`s (`[lengthByte, ascii...]`), and manually patch COFF `Characteristics |= 0x0020` (`IMAGE_FILE_LARGE_ADDRESS_AWARE`) on 32-bit `.exe` hosts.

#### Design
Extend `PeImageEditor` and `PeHeaderParser` with zero external NuGet dependencies across all 5 TFMs:

```csharp
public sealed class PeImportModuleRemoval
{
    public required string ModuleName { get; init; }

    /// <summary>
    /// Required for idempotent re-application on an already-compacted worker image:
    /// identifies an import module expected to remain present in the import table when
    /// <see cref="ModuleName"/> has already been removed.
    /// </summary>
    public string? WitnessRemainingModuleName { get; init; }
}

public sealed class PeImageEditor
{
    public ushort Characteristics { get; }
    public uint TimeDateStamp { get; }
    public uint SizeOfImage { get; }

    public uint FileOffsetToRva(int fileOffset);

    public PeImageEditor RewriteExportModuleName(
        string originalModuleName,
        string replacementModuleName);

    public PeImageEditor RemoveImportModule(
        PeImportModuleRemoval removal);

    public PeImageEditor ReplaceVerifiedAsciiStringAtRva(
        uint rva,
        string expectedOriginal,
        string replacement,
        bool requireNullTerminator = true);

    public PeImageEditor ReplaceVerifiedUtf16StringAtRva(
        uint rva,
        string expectedOriginal,
        string replacement,
        bool requireNullTerminator = true);

    public PeImageEditor ReplaceVerifiedShortStringAtRva(
        uint rva,
        string expectedOriginal,
        string replacement,
        bool allowAnyPrintableAsciiOfSameLength = false);

    public PeImageEditor SetLargeAddressAware(bool enabled = true);
}
```

Also add `PeImageValidationOptions.ForExecutable(ushort? expectedMachine = null, long? expectedFileLength = null)` (setting `RequireDll = false`, `RequireUnmanagedImage = true`) so helper `.exe` binaries (`RemoveImportModule` and `SetLargeAddressAware`) pass upfront COFF validation cleanly without relaxing default DLL checks.

And add `public bool RewriteExportModuleName { get; init; }` (default `false` or opt-in when `RenameForWorker = true`) on `IsolatedModuleSpecification` so `IsolatedLibrarySet` can rewrite a renamed module's export header in the same pass as its import descriptors.

#### Key invariants
- `RewriteExportModuleName` validates `DataDirectory[0]` (`ExportTable`) bounds, ensures the target RVA resolves inside a mapped section, verifies exact case-insensitive ASCII match against either `originalModuleName` or `replacementModuleName` (idempotent), enforces `replacementModuleName.Length <= originalModuleName.Length` with `PeNameValidator`, and NUL-pads trailing bytes up to the original NUL terminator.
- `RemoveImportModule` walks bounded 20-byte `IMAGE_IMPORT_DESCRIPTOR` entries until the all-zero terminator:
  - Rejects truncated or section-crossing descriptor arrays with `BadImageFormatException`.
  - Removes all descriptors matching `ModuleName` (ASCII case-insensitive), shifts remaining descriptors contiguously, zero-fills vacated descriptor slots at the tail, and updates `DataDirectory[1].Size` when appropriate without stranding unreferenced ILT/IAT thunks.
  - Requires `WitnessRemainingModuleName` (or an explicit non-empty import table witness) to succeed idempotently when `ModuleName` is already absent; otherwise throws `BadImageFormatException` so typos in `ModuleName` never silently succeed!
- `ReplaceVerifiedAsciiStringAtRva` / `ReplaceVerifiedUtf16StringAtRva` reject embedded NULs, enforce `replacement.Length <= expectedOriginal.Length`, verify the existing NUL terminator when `requireNullTerminator = true`, zero-pad unused trailing character slots, and accept either `expectedOriginal` or zero-padded `replacement` for idempotence.
- `ReplaceVerifiedShortStringAtRva` validates Borland Delphi / Pascal `ShortString` slots (`buffer[rva] == length`, `buffer[rva + 1 .. rva + length] == printable ASCII`, length `1..255`), enforces `replacement.Length <= expectedOriginal.Length`, writes `[ (byte)replacement.Length, ascii..., zero-padding ]`, and when `allowAnyPrintableAsciiOfSameLength = true` accepts any existing printable-ASCII `ShortString` of exact `expectedOriginal.Length` (supporting base images whose fixed-length `.INI` reference was previously customized).
- `SetLargeAddressAware` mutates COFF `Characteristics` (`0x0020`) in memory and requires `ClearAuthenticodeAndRecalculateChecksum()` before saving signed images (consistent with existing `PeImageEditor` mutations).

#### Acceptance
- Tested on real `PE32` (`x86`) and `PE32+` (`x64`) native fixture binaries:
  - `RewriteExportModuleName` updates `IMAGE_EXPORT_DIRECTORY.Name` and rejects oversized/non-ASCII names and mismatched originals.
  - `RemoveImportModule` removes a real unused companion DLL descriptor from a fixture binary so `UnmanagedLibrary` loads the patched binary cleanly even when the removed companion DLL file is deleted from disk, while rejecting unverified missing module names with `BadImageFormatException`.
  - `ReplaceVerifiedAsciiStringAtRva`, `ReplaceVerifiedUtf16StringAtRva`, `FileOffsetToRva`, and `SetLargeAddressAware` verify round-trip correctness and idempotence.

### UNM-08 (P0): Loaded-module runtime IAT redirection & verified in-memory RVA primitives (`LoadedModuleMemory`)

#### Evidence
Offline PE patching is not always sufficient or desirable:
1. **Runtime IAT redirection to dynamic managed/native stubs:** Redirecting an imported Win32 API (`SHGetFolderPathW`, `RegCreateKeyExA`, `OleCreate`, `CoCreateInstance`) inside a loaded DLL to an `[UnmanagedCallersOnly]` / delegate function pointer requires runtime addresses known only inside the live process. Walking the mapped PE's `IMAGE_IMPORT_DESCRIPTOR` (`OriginalFirstThunk` ILT + `FirstThunk` IAT) eliminates fragile hardcoded IAT slot RVAs.
2. **Verified in-memory patching & reusable-session `.data`/`.bss` scratch clearing:** Legacy VB6/Fortran/C DLLs often leak mutable `.bss` state across calls or require writing a runtime heap pointer into a verified `.data` RVA. Verifying the loaded module's `TimeDateStamp`, `SizeOfImage`, and section characteristics before writing/zeroing memory makes reusable sessions fast and safe without reloading DLLs per request.

#### Design
Introduce a Windows-only `[SupportedOSPlatform("windows")]` `LoadedModuleMemory` static/instance utility working on `SafeLibraryHandle` / `UnmanagedLibrary`:

```csharp
[SupportedOSPlatform("windows")]
public readonly struct LoadedModuleIdentity : IEquatable<LoadedModuleIdentity>
{
    public PeMachine Machine { get; init; }
    public uint TimeDateStamp { get; init; }
    public uint SizeOfImage { get; init; }
}

[SupportedOSPlatform("windows")]
public static class LoadedModuleMemory
{
    public static LoadedModuleIdentity Inspect(SafeLibraryHandle libraryHandle);

    public static void VerifyIdentity(
        SafeLibraryHandle libraryHandle,
        LoadedModuleIdentity expected);

    public static IntPtr RedirectImportFunction(
        SafeLibraryHandle libraryHandle,
        string importedModuleName,
        string exportName,
        IntPtr replacementFunction);

    public static bool TryRedirectImportFunction(
        SafeLibraryHandle libraryHandle,
        string importedModuleName,
        string exportName,
        IntPtr replacementFunction,
        out IntPtr originalFunction);

    public static bool TryRedirectImportOrdinal(
        SafeLibraryHandle libraryHandle,
        string importedModuleName,
        ushort ordinal,
        IntPtr replacementFunction,
        out IntPtr originalFunction);

    public static void WriteVerifiedBytesAtRva(
        SafeLibraryHandle libraryHandle,
        LoadedModuleIdentity expectedIdentity,
        uint rva,
        ReadOnlySpan<byte> expectedCurrentBytes,
        ReadOnlySpan<byte> replacementBytes,
        bool flushInstructionCache = false);

    public static void ClearWritableBytesAtRva(
        SafeLibraryHandle libraryHandle,
        LoadedModuleIdentity expectedIdentity,
        uint rva,
        int byteCount);
}
```

#### Key invariants
- **Handle lifetime safety:** Every operation acquires `DangerousAddRef` on `SafeLibraryHandle` for the duration of header inspection and memory modification, throwing `ObjectDisposedException` on closed/invalid handles and `PlatformNotSupportedException` on non-Windows platforms.
- **Datafile mapping rejection:** Rejects `LOAD_LIBRARY_AS_DATAFILE` / `LOAD_LIBRARY_AS_IMAGE_RESOURCE` handles (`(rawHandle & 3) != 0`) because datafile mappings do not resolve IAT thunks or map sections at virtual RVA offsets.
- **Bounded mapped-PE parsing:** Validates `DOS` (`MZ`), `PE\0\0`, bitness match (`PE32` in 32-bit process, `PE32+` in 64-bit process), and `SizeOfImage` bounds before dereferencing any RVA in memory.
- **IAT redirection safety (`TryRedirectImportFunction` / `TryRedirectImportOrdinal`):**
  - Requires `OriginalFirstThunk != 0` (unbound ILT metadata present) so symbol names/ordinals can be matched deterministically even if an IAT slot was already redirected earlier! (Returns the *current* IAT slot pointer as `originalFunction` so callers can chain or restore deterministically.)
  - Validates that `replacementFunction != IntPtr.Zero`.
  - Temporarily changes protection on the single pointer slot (`IntPtr.Size` bytes) via `VirtualProtect(..., PAGE_READWRITE, out oldProtect)`, performs a pointer-sized volatile/atomic write, and restores `oldProtect` in a `finally` block.
- **Verified RVA write & writable-section clear safety:**
  - Requires `LoadedModuleIdentity` (`Machine`, `TimeDateStamp`, `SizeOfImage`) verification first so an updated DLL binary fails closed with `BadImageFormatException` instead of corrupting shifted globals.
  - `ClearWritableBytesAtRva` verifies that `[rva, rva + byteCount)` falls completely within a mapped section carrying `IMAGE_SCN_MEM_WRITE` (`0x80000000`) and NOT `IMAGE_SCN_MEM_EXECUTE`, preventing accidental zeroing of `.text` or `.rdata` without `VirtualProtect` tricks.
  - `WriteVerifiedBytesAtRva` accepts either `expectedCurrentBytes` or `replacementBytes` (idempotent), uses `VirtualProtect` when targeting read-only sections (`.rdata` / `.text`), restores original page protection in `finally`, and calls `FlushInstructionCache(GetCurrentProcess(), ...)` when `flushInstructionCache = true` or target section has `IMAGE_SCN_MEM_EXECUTE`.

#### Acceptance
- Native C fixture exports:
  1. A function calling an imported companion/Win32 function (`iso_child_compute` or `GetTickCount`), redirected at runtime via `LoadedModuleMemory.RedirectImportFunction` to a C# callback/function pointer, then restored to `originalFunction` and verified on both `x64` and `x86` across all 5 TFMs.
  2. A mutable `.data`/`.bss` scratch buffer cleared via `ClearWritableBytesAtRva` (and verified that attempting to clear `.rdata`/`.text` throws `InvalidOperationException` / `BadImageFormatException`).
  3. A read-only `.rdata` constant modified idempotently via `WriteVerifiedBytesAtRva` with mismatched `LoadedModuleIdentity` failing closed with `BadImageFormatException`.

### UNM-09 (P1): Address-to-module provenance & loaded-module path introspection (`UnmanagedLibrary`)

#### Evidence
Downstream multi-worker test suites and COM/native diagnostics call `GetModuleHandleExW(GET_MODULE_HANDLE_EX_FLAG_FROM_ADDRESS | GET_MODULE_HANDLE_EX_FLAG_UNCHANGED_REFCOUNT, address, out module)` + `GetModuleFileNameW` (with dynamic buffer growth beyond `MAX_PATH = 260` for long paths) to assert which physical worker DLL backs a function pointer or vtable slot.

#### Design
Add Windows-only module introspection helpers on `UnmanagedLibrary`:

```csharp
public sealed partial class UnmanagedLibrary
{
    [SupportedOSPlatform("windows")]
    public string GetLoadedFilePath();

    [SupportedOSPlatform("windows")]
    public bool ContainsAddress(IntPtr address);

    [SupportedOSPlatform("windows")]
    public static string GetLoadedFilePath(SafeLibraryHandle safeLibraryHandle);

    [SupportedOSPlatform("windows")]
    public static bool TryGetLoadedModuleFromAddress(
        IntPtr address,
        out IntPtr moduleBaseAddress,
        out string? moduleFilePath);

    [SupportedOSPlatform("windows")]
    public static IntPtr GetRequiredSystemExport(
        string systemModuleName,
        string exportName);
}
```

#### Key invariants
- `GetLoadedFilePath` uses a loop doubling buffer capacity (`260 -> 520 -> ... -> 32768` chars) around `GetModuleFileNameW` so `\\?\` long paths never truncate silently.
- `TryGetLoadedModuleFromAddress` rejects `IntPtr.Zero` cleanly (`return false`) and calls `GetModuleHandleExW(GET_MODULE_HANDLE_EX_FLAG_FROM_ADDRESS, address, out module)` (temporarily incrementing the module reference count rather than passing `GET_MODULE_HANDLE_EX_FLAG_UNCHANGED_REFCOUNT`) paired with `FreeLibrary` in `finally`, eliminating any use-after-free race if another thread unloads the module while `GetModuleFileNameW` resolves its path.
- `ContainsAddress` checks `DangerousAddRef` + `TryGetLoadedModuleFromAddress` (or mapped `[BaseAddress, BaseAddress + SizeOfImage)`) against the live `UnmanagedLibrary` instance.
- `GetRequiredSystemExport` validates that `systemModuleName` is a bare file name (no directory separators or drive specifiers), loads/resolves strictly via `LoadLibraryExW(systemModuleName, IntPtr.Zero, LOAD_LIBRARY_SEARCH_SYSTEM32)` (`0x00000800`) to prevent working-directory DLL planting, and throws `EntryPointNotFoundException` if `GetProcAddress` returns `IntPtr.Zero` (providing safe target resolution when wiring `LoadedModuleMemory` IAT redirects to OS exports).

#### Acceptance
- Verified across two concurrent `IsolatedLibrarySet` instances (`worker 0` and `worker 1`): export addresses from worker 0 resolve to worker 0's physical `.dll` path, `worker0Lib.ContainsAddress(export0)` is `true`, `worker0Lib.ContainsAddress(export1)` is `false`, `GetRequiredSystemExport("kernel32.dll", "CompareStringW")` succeeds while path-qualified names throw `ArgumentException`, and `IntPtr.Zero` / unmapped heap addresses return `false`.

### UNM-10 (P1): Companion asset staging, legacy path-constraint validation & process-pinned mode (`IsolatedLibrarySet`)

#### Evidence
In production worker directories:
1. DLLs expect non-DLL files alongside them (`config.ini`, `catalog.dat`, `.mdb` databases, `.manifest` files, or subdirectories of lookup tables). Currently callers must reach into `IsolatedLibrarySet.WorkerDirectory` *after* `Load()`—which is **too late** if `DllMain` opens `config.ini` during `LoadLibraryExW`!
2. Legacy runtimes (Jet 4.0 `.mdb` paths `<= 120` ASCII chars, Fortran `CHARACTER*128`, Delphi ANSI `MAX_PATH`) fail with cryptic native error codes if `WorkerDirectory` is non-ASCII or exceeds a fixed character budget.
3. Certain legacy DLLs spawn unmanaged background threads or register broken TLS callbacks that crash the process if `FreeLibrary` is ever called; hosts intentionally pin those worker modules for process lifetime while keeping the directory lease active.

#### Design
Extend `IsolatedLibrarySetOptions` with pre-load companion file and directory-tree specifications, path guards, and explicit process-lifetime pinning:

```csharp
public enum CompanionCopyMode
{
    CopyIfDifferentSizeOrTimestamp = 0,
    OverwriteAlways = 1,
}

public sealed class IsolatedCompanionFileSpecification
{
    public required string SourceRelativePath { get; init; }
    public string? TargetRelativePath { get; init; }
    public CompanionCopyMode CopyMode { get; init; } = CompanionCopyMode.CopyIfDifferentSizeOrTimestamp;
    public Func<byte[], string, byte[]>? TransformBytes { get; init; }
}

public sealed class IsolatedCompanionDirectorySpecification
{
    public required string SourceRelativePath { get; init; }
    public string? TargetRelativePath { get; init; }
    public string SearchPattern { get; init; } = "*";
    public bool Recursive { get; init; } = true;
    public CompanionCopyMode CopyMode { get; init; } = CompanionCopyMode.CopyIfDifferentSizeOrTimestamp;
}

public sealed class IsolatedLibrarySetOptions
{
    // Existing properties preserved...
    public IReadOnlyList<IsolatedCompanionFileSpecification> CompanionFiles { get; init; } =
        Array.Empty<IsolatedCompanionFileSpecification>();

    public IReadOnlyList<IsolatedCompanionDirectorySpecification> CompanionDirectories { get; init; } =
        Array.Empty<IsolatedCompanionDirectorySpecification>();

    public int? MaxWorkerFilePathLength { get; init; }
    public bool RequireAsciiWorkerPaths { get; init; }
    public bool PinModulesForProcessLifetime { get; init; }
}
```

#### Key invariants
- **Staged before `DllMain`:** All `CompanionDirectories` and `CompanionFiles` are validated (no `..` path traversal outside `SourceDirectory` or `WorkerDirectory`, no embedded NULs, no collision with staged DLL target filenames) and written atomically **before** topological `UnmanagedLibrary` loading begins, so `DllMain` sees every `.ini`/`.dat`/`.manifest` and lookup-table subdirectory immediately.
- **Path-constraint preflight:** Before creating files or loading modules, if `MaxWorkerFilePathLength` or `RequireAsciiWorkerPaths` is set, every computed target DLL and companion file path is checked up front, throwing a descriptive `PathTooLongException` / `ArgumentException` naming the offending path and limit.
- **Safe process-lifetime pinning (`PinModulesForProcessLifetime = true`):**
  - When enabled, `Dispose()` intentionally skips `FreeLibrary`, keeps the process-wide companion filename reservation and `.unmanaged-isolation.lease` handle alive for process lifetime (so neither another in-process set nor `SweepStaleWorkerDirectories` can delete or reuse the still-mapped files!), and marks the managed `IsolatedLibrarySet` wrapper disposed so callers get `ObjectDisposedException` on post-dispose access.

#### Acceptance
- Native fixture `DllMain` / init export reads a staged `.cfg` companion file from its load directory during initialization; test verifies `TransformBytes` (e.g., writing `WorkerDirectory` into `.ini`), path-traversal rejection (`../secret`), `MaxWorkerFilePathLength` / `RequireAsciiWorkerPaths` preflight failure, and `PinModulesForProcessLifetime` preserving loaded module memory and lease protection across `Dispose()` and `SweepStaleWorkerDirectories`.

### UNM-11 (P2): Bounded reusable worker slot lease allocator (`WorkerSlotAllocator`)

#### Evidence
When a companion DLL has a 4–6 character stem (`core.dll`, `calc.dll`, `mesh.dll`, `unit01.dll`), fixed-length worker renaming (`WorkerModuleNaming.FormatFixedLengthName`) only has room for a 2-digit decimal or base-36 suffix (`co00.dll`..`co99.dll`, `00..99`) and cannot embed a separate `Generation` prefix:
- When sessions recycle dynamically outside a fixed worker index (or overlap briefly during session replacement), callers maintain ad-hoc `bool[100]` slot tables (including excluded slots like `slot != 32` where `"co32.dll"` would collide with an OS module name).
- Furthermore, dedicated worker session factories often track `[ThreadStatic] int? _preferredThreadSlot` so that when session teardown releases a slot during recycling and session creation immediately runs on the **same worker thread**, the worker re-acquires its previous slot (`workerIndex`) instead of scanning from `0` and forcing `IsolatedLibrarySet` to re-stage/re-patch a different worker slot's directory.

#### Design
Provide a small, thread-safe, lock-based bounded integer slot allocator supporting excluded slots, explicit preferred-slot hints, and optional thread-sticky slot reuse:

```csharp
public sealed class WorkerSlotAllocator
{
    public WorkerSlotAllocator(
        int maxExclusive = 100,
        IEnumerable<int>? excludedSlots = null,
        bool preferThreadStickySlot = false);

    public int Capacity { get; }
    public int AvailableCount { get; }

    public WorkerSlotLease Acquire(int? preferredSlot = null);
    public bool TryAcquire(out WorkerSlotLease? lease, int? preferredSlot = null);
}

public sealed class WorkerSlotLease : IDisposable
{
    public int SlotIndex { get; }
    public void Dispose();
}
```

#### Key invariants
- Resolution order under lock:
  1. Explicit `preferredSlot` if in `[0, maxExclusive)`, not excluded, and currently free.
  2. When `preferThreadStickySlot == true`, the calling thread's last-released slot for this allocator instance (tracked per-allocator / `[ThreadStatic]` weak or allocator-id keyed cache so multiple `WorkerSlotAllocator` instances never cross-contaminate preferred slots) if currently free.
  3. Deterministic lowest-available-slot scan (`0..maxExclusive - 1`), skipping `excludedSlots` (validated in `[0, maxExclusive)`).
- Idempotent `WorkerSlotLease.Dispose()` using `Interlocked.Exchange` so double-dispose can never release a slot re-acquired by another caller, updating the releasing thread's sticky slot hint when `preferThreadStickySlot == true`.
- Throws `ArgumentOutOfRangeException` when `preferredSlot` is outside `[0, maxExclusive)` and `InvalidOperationException` on `Acquire(...)` when all non-excluded slots are currently leased.

#### Acceptance
- Unit tests cover lowest-slot reuse, explicit `preferredSlot` hint hit and occupied fallback, `preferThreadStickySlot` recycling on the same dedicated worker thread without cross-allocator interference, excluded-slot skipping, exhaustion (`TryAcquire == false` / `Acquire` throws), idempotent double-`Dispose()`, and parallel contention across 32 threads.

### UNM-12 (P2): Zero-allocation fixed-buffer byte-string marshaling (`NativeByteString`) & opt-in `win-x86` `LargeAddressAware` MSBuild target

#### Evidence
1. **Fixed-width C / Fortran / Delphi string buffers:** Native wrappers repeatedly reimplement `Span<byte>` encoding/decoding for NUL-terminated ASCII/Latin1 strings, Fortran trailing-space-padded `CHARACTER*N` buffers (`' ' = 0x20`, no NUL terminator), and Borland Delphi length-prefixed `ShortString`s (`buffer[0] = length`, `buffer[1..length] = bytes`).
2. **32-bit `win-x86` virtual address exhaustion:** Each isolated multi-DLL set reserves several megabytes of virtual address space (`ImageBase` relocations + CRT/Fortran static `.bss`). On 64-bit Windows, a default 32-bit `.NET` apphost `.exe` is capped at `2 GiB` unless `IMAGE_FILE_LARGE_ADDRESS_AWARE` (`0x0020`) is set in its COFF header, which doubles usable user-mode VA space to `4 GiB` without requiring external `editbin.exe` from Visual Studio C++ tools.

#### Design
1. Add `NativeByteString` (pure `Span<byte>` / `ReadOnlySpan<byte>` on `net10.0`+ and `byte[]` + `Span<byte>` via `System.Memory` where available, or zero-dependency `byte[]` overloads on `net472`–`net481` so **no new NuGet dependency** is added on `.NET Framework`):

```csharp
public static class NativeByteString
{
    // NUL-terminated single-byte (ASCII / ISO-8859-1 Latin1)
    public static int WriteNullTerminatedAscii(string value, byte[] destination, int offset, int count);
    public static string ReadNullTerminatedAscii(byte[] source, int offset, int count);
    public static string ReadNullTerminatedLatin1(byte[] source, int offset, int count);

    // Space-padded fixed-width Fortran CHARACTER*N
    public static void WriteSpacePaddedAscii(string value, byte[] destination, int offset, int count);
    public static string ReadSpacePaddedAscii(byte[] source, int offset, int count);

    // Length-prefixed Pascal / Delphi ShortString (capacity <= 255 + 1 length byte)
    public static void WriteShortStringAscii(string value, byte[] destination, int offset, int capacity);
    public static string ReadShortStringAscii(byte[] source, int offset, int maxLength);

#if NET5_0_OR_GREATER
    public static int WriteNullTerminatedAscii(ReadOnlySpan<char> value, Span<byte> destination);
    public static string ReadNullTerminatedAscii(ReadOnlySpan<byte> source);
    public static string ReadNullTerminatedLatin1(ReadOnlySpan<byte> source);
    public static void WriteSpacePaddedAscii(ReadOnlySpan<char> value, Span<byte> destination);
    public static string ReadSpacePaddedAscii(ReadOnlySpan<byte> source);
    public static void WriteShortStringAscii(ReadOnlySpan<char> value, Span<byte> destination);
    public static string ReadShortStringAscii(ReadOnlySpan<byte> source);
#endif
}
```

2. Ship an **opt-in** `buildTransitive/AdaskoTheBeAsT.Interop.Unmanaged.targets` inside the NuGet package:
   - Controlled by `<EnableLargeAddressAwareAppHost>true</EnableLargeAddressAwareAppHost>` (default **`false`**, so existing consumers experience zero build behavior change unless they opt in).
   - When enabled on `win-x86` / `PlatformTarget=x86` executable projects (`OutputType == Exe` or `WinExe`), runs a lightweight inline MSBuild `RoslynCodeTaskFactory` task hooked at **`AfterTargets="_CreateAppHost"`** on `$(AppHostIntermediatePath)` (so SDK `_CopyAppHostToOutputDirectory`, incremental builds, and referencing test projects receive the patched apphost before copy) **and** at **`AfterTargets="Publish"`** on `$(PublishDir)$(AssemblyName).exe`, validating `MZ`/`PE\0\0` + `Machine == 0x014C` (`IMAGE_FILE_MACHINE_I386`), executable non-DLL COFF characteristics, and `PE32` magic (`0x010B`) before setting `IMAGE_FILE_LARGE_ADDRESS_AWARE` (`0x0020`) idempotently without requiring `editbin.exe`.

#### Key invariants
- `NativeByteString.Write*` rejects embedded NULs (`'\0'`), non-ASCII characters (`> 0x7F`) on `*Ascii` methods, and strings exceeding fixed buffer capacity (reserving 1 byte for NUL in `WriteNullTerminatedAscii`, and `<= 255` bytes in `WriteShortStringAscii`), zeroing trailing bytes deterministically so stack/pooled buffers never leak stale memory into native calls.
- Keeping `Span<T>` overloads `#if NET5_0_OR_GREATER` and providing `byte[]` overloads across all TFMs preserves **zero external NuGet package dependencies** on `net472`, `net48`, and `net481`!
- `AdaskoTheBeAsT.Interop.Unmanaged.targets` is strictly no-op unless `$(EnableLargeAddressAwareAppHost) == 'true'`, touches only `I386` PE32 apphost/executable outputs, and updates `Validate-Package.ps1` to assert `buildTransitive/AdaskoTheBeAsT.Interop.Unmanaged.targets` is packed cleanly.

#### Acceptance
- `NativeByteString` unit tests verify C NUL-terminated, Fortran space-padded, and Delphi `ShortString` round-trips, buffer-boundary edge cases, non-ASCII / embedded-NUL rejection, and trailing-byte zeroing across all 5 TFMs.
- Integration test / `Validate-Package.ps1` verifies the packed `buildTransitive` target sets `0x0020` on both built (`_CreateAppHost` -> `TargetDir`) and published (`PublishDir`) `win-x86` apphosts when `EnableLargeAddressAwareAppHost=true` and leaves binaries untouched when `false`.

### UNM-13 (P2): Fault-evicting process-pinned handle cache (`PinnedLibraryCache<TKey, THandles>`) & reusable zeroed native scratch buffer (`UnmanagedScratchBuffer`)

#### Evidence
1. **Duplicated process-pinned handle caches + load locks across unload-unsafe DLL hosts:**
   - Legacy 32-bit Borland Delphi RTL, PowerBASIC, and MFC DLLs can crash with access violations or dangling TLS/child-process state if unloaded via `FreeLibrary` and reloaded in the same process.
   - `IsolatedLibrarySetOptions.PinModulesForProcessLifetime = true` (`UNM-10`) suppresses `FreeLibrary` on `Dispose()`, **but** when worker sessions recycle or default instances are requested repeatedly, callers also need to reuse the already-loaded `UnmanagedLibrary` / `IsolatedLibrarySet` handles, bound export delegates, and one-time native path initializers without re-running initialization or suppressing `CA2000` / `IDISP001` / `IDISP003` at every call site.
   - Downstream wrappers repeatedly implement `ConcurrentDictionary.GetOrAdd` paired with an external static lock or `ConcurrentDictionary<string, Lazy<NativeHandles>>` (`ExecutionAndPublication`) with manual fault-eviction on `catch` so a transient initialization failure is not permanently cached by `Lazy<T>`.
2. **Duplicated `Marshal.AllocHGlobal` / `SafeBuffer` native scratch buffers:**
   - Sessions calling native `ref char*` / mutable byte-block ABIs repeatedly write custom `Marshal.AllocHGlobal` / `FreeHGlobal` wrappers and manual `DangerousAddRef` / `DangerousRelease` `try / finally` blocks (`#pragma warning disable S3869`).

#### Design
1. Add thread-safe, single-flight, fault-evicting `PinnedLibraryCache<TKey, THandles>` (plus string-keyed factory `PinnedLibraryCache.CreateOrdinalIgnoreCase<THandles>()`):

```csharp
public sealed class PinnedLibraryCache<TKey, THandles>
    where TKey : notnull
    where THandles : class
{
    public PinnedLibraryCache(IEqualityComparer<TKey>? comparer = null);

    public int Count { get; }

    public THandles GetOrLoad(
        TKey key,
        Func<TKey, THandles> loader);

    public bool TryGet(
        TKey key,
        [NotNullWhen(true)] out THandles? handles);
}
```

2. Add reusable zero-initialized `UnmanagedScratchBuffer : SafeBuffer` with an RAII pointer-retention scope:

```csharp
public sealed class UnmanagedScratchBuffer : SafeBuffer
{
    public UnmanagedScratchBuffer(int byteLength, bool zeroMemory = true);

    public int ByteLength { get; }

    public void Clear();
    public void Clear(int byteOffset, int byteCount);

    public PointerLease AcquirePointerLease();

    public ref struct PointerLease
    {
        public IntPtr Pointer { get; }
        public int ByteLength { get; }
        public void Dispose();
    }
}
```

#### Key invariants
- `PinnedLibraryCache<TKey, THandles>.GetOrLoad`:
  - Guarantees **single-flight per key**: concurrent callers requesting the same `key` wait on the same `Lazy<THandles>(LazyThreadSafetyMode.ExecutionAndPublication)` entry rather than loading or initializing the native DLL twice.
  - **Evicts faulted entries atomically:** if `loader(key)` throws (or returns `null`, rejected with `InvalidOperationException`), removes only that exact faulted `Lazy<THandles>` instance before rethrowing so subsequent retries can succeed cleanly.
  - Intentionally retains loaded `THandles` for process lifetime without callers needing `#pragma warning disable CA2000, IDISP001, IDISP003`.
- `UnmanagedScratchBuffer`:
  - Rejects `byteLength <= 0` with `ArgumentOutOfRangeException`, allocates unmanaged memory via `Marshal.AllocHGlobal(byteLength)`, calls `Initialize((ulong)byteLength)`, zero-fills deterministically when `zeroMemory = true`, and frees via `Marshal.FreeHGlobal` in `ReleaseHandle()`.
  - `AcquirePointerLease()` calls `DangerousAddRef` on entry (throwing `ObjectDisposedException` if closed) and `DangerousRelease` in `Dispose()` idempotently, keeping the buffer pinned across raw `IntPtr` / `ref IntPtr` P/Invoke calls cleanly.

#### Acceptance
- `PinnedLibraryCache` unit tests across all 5 TFMs verify single-flight execution under 16-thread contention for the same key, independent parallel loading across distinct keys, fault eviction followed by clean retry recovery when the first load throws, and `null`-return rejection.
- `UnmanagedScratchBuffer` unit tests verify zero-initialization, bounded `Clear(...)` range validation, `AcquirePointerLease()` reference retention and idempotent release, and `ObjectDisposedException` after `Dispose()`.
